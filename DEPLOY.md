# Deploying FinTrackPro

FinTrackPro has three hostable parts, plus the mobile app:

| Piece         | What it is                        | Where it runs                          |
| ------------- | --------------------------------- | -------------------------------------- |
| **API**       | Node + Express (`server/`)        | A container/Node host                  |
| **Database**  | Postgres                          | A managed Postgres                     |
| **Web app**   | Expo web static build (`dist/`)   | Any static host / CDN                  |
| **Mobile**    | iOS / Android build               | EAS Build → stores or internal (see `EAS.md`) |

> Free tiers and pricing on every provider below change often — check the
> provider's current pricing page. Free API instances usually "cold start"
> after idle, so the first request may take a few seconds.

---

## Fastest path — everything on Render (one blueprint)

This repo ships a **`render.yaml`** that provisions the database, the API, and
the web app together.

1. Push the repo to GitHub (you've done this: `vincentdit/Fintrackpro`).
2. Go to **[render.com](https://render.com)** → **New +** → **Blueprint**.
3. Connect the repo. Render reads `render.yaml` and shows the three resources:
   `fintrackpro-db`, `fintrackpro-api`, `fintrackpro-web`. Click **Apply**.
4. Wait for the first deploy. Render gives each service a URL, e.g.
   - API: `https://fintrackpro-api.onrender.com`
   - Web: `https://fintrackpro-web.onrender.com`
5. **Wire the two URLs together** (they aren't known until after step 4):
   - In **fintrackpro-api → Environment**, set
     `CORS_ORIGIN = https://fintrackpro-web.onrender.com`
   - In **fintrackpro-web → Environment**, set
     `EXPO_PUBLIC_API_BASE_URL = https://fintrackpro-api.onrender.com`
   - **Redeploy the web service** (its API URL is baked in at build time).
6. Open the web URL, create an account, and you're live. Point your phone at
   the same API (see "Mobile" below).

`JWT_SECRET` is generated by Render, `DATABASE_URL` is injected from the managed
Postgres, and `DATABASE_SSL=true` is set — the server enables TLS automatically.
The database migrates itself on first boot.

## À la carte (mix and match)

### API + database

Any of these build the API from `server/Dockerfile` and give you a Postgres:

- **Render** — as above (Docker service + managed Postgres).
- **Railway** ([railway.app](https://railway.app)) — "New Project → Deploy from
  repo", add a **Postgres** plugin; set the service root to `server/`. Railway
  injects `DATABASE_URL`. Add env `DATABASE_SSL=true`, `JWT_SECRET=<random>`,
  `CORS_ORIGIN=<your web URL>`.
- **Fly.io** ([fly.io](https://fly.io)) — `fly launch` in `server/` (it detects
  the Dockerfile), `fly postgres create` then `fly postgres attach`. Set the
  same env vars with `fly secrets set`.

Required env vars for the API:

| Var             | Value                                             |
| --------------- | ------------------------------------------------- |
| `DATABASE_URL`  | Postgres connection string (host injects this)    |
| `DATABASE_SSL`  | `true` for managed Postgres                       |
| `JWT_SECRET`    | a long random string (**required in production**) |
| `CORS_ORIGIN`   | your web app URL(s), comma-separated              |
| `PORT`          | provided by the host; defaults to 4000            |

### Web app (static)

The web build is a static site. Build command and output are the same everywhere:

```
Build command:  npm install --legacy-peer-deps && npx expo export -p web
Publish dir:    dist
Env var:        EXPO_PUBLIC_API_BASE_URL = https://<your-api-host>
```

`EXPO_PUBLIC_API_BASE_URL` is **baked in at build time**, so set it before/at the
build and redeploy if the API URL changes. Hosts that work out of the box:
**Netlify**, **Vercel**, **Cloudflare Pages**, or **GitHub Pages** (add a SPA
fallback to `index.html`).

### Mobile app

The phone app just needs to point at the hosted API:

- **Quick (Expo Go / dev):** run Metro with the API URL, e.g.
  `EXPO_PUBLIC_API_BASE_URL=https://fintrackpro-api.onrender.com npx expo start`.
- **Real builds:** see `EAS.md`. Set `EXPO_PUBLIC_API_BASE_URL` in `eas.json`'s
  build profile `env`, then `eas build`. Distribute via internal link (APK /
  TestFlight) or submit to the stores with `eas submit`.

## Production checklist

- [ ] `JWT_SECRET` is a long random value (never the dev default).
- [ ] `CORS_ORIGIN` is set to your web origin(s), not left open.
- [ ] `DATABASE_SSL=true` against managed Postgres; database backups enabled.
- [ ] HTTPS everywhere (managed hosts give you TLS automatically).
- [ ] Consider a paid API tier if you don't want cold starts.
- [ ] Rotate `JWT_SECRET` only when you're ready to invalidate all sessions.

## After deploy, verify

```bash
curl https://<your-api-host>/health          # -> {"ok":true}
```

Then register on the web app and log in on your phone — an edit on one shows up
on the other, now entirely in the cloud.
